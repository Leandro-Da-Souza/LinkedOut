# Milestone 1.5: private factual knowledge

## Small architectural extension

The shared drafting service depends on a small `KnowledgeReader` interface. Its implementation scans the private `knowledge/` tree, extracts readable text, and maintains a separate derived SQLite FTS5 index inside that directory. The existing draft database and MCP tools remain intact. An agent run retrieves one evidence snapshot from the original brief and passes that same snapshot to the shared drafting handler.

PDF extraction uses the maintained [Poppler library](https://poppler.pages.freedesktop.org/poppler-web-page/) through its `pdftotext` utility. This works locally without a new npm dependency, a renderer, browser, network endpoint or handwritten PDF parser. The tradeoff is an OS-level dependency and PDF layout limitations. Extraction is a separate process with fixed arguments, no shell, no inherited credentials, ignored raw stderr, a timeout, private temporary files and bounded input/pages/output. Scanned PDFs require separate local OCR; encrypted or malformed documents produce safe diagnostic codes. Markdown/plain text use strict UTF-8 decoding without executing or fetching document content.

[SQLite FTS5](https://www.sqlite.org/fts5.html) provides token matching and BM25 ranking. No embeddings, vectors, semantic search framework, learned memory or additional server is introduced. Lexical search can miss synonyms and short technology names; use explicit project/technology terms and inspect `knowledge search` results. Selection is capped at six passages/6000 characters, with at most two passages per document, rather than feeding every document to the model.

Content hashes identify revisions, and chunk identifiers include the document/revision. Unchanged files reuse extracted passages; edits, removals, malformed replacements and unsafe links stop supplying old evidence. Both drafting modes include the snapshot in idempotency fingerprints. A changed knowledge corpus conflicts with an old key rather than silently replaying a stale draft. This is conservative: an unrelated file edit can also change the corpus revision.

## Two-stage grounding and review contract

Generation (`draft-v4-body-only`) returns `{ body, warnings }`, with no citation metadata. The application validates and freezes the body for assessment by retaining its own copy; neither provider receives a mutable reference to the stored body or evidence snapshot. Both stages use the same retrieved evidence. Identity/style preferences are not evidence, and knowledge never enters the planner prompt.

The assessor (`assessment-v2`) receives application-created text units with IDs and text, plus retrieved source IDs/excerpts. It receives no offsets, profile, writing samples, file paths or full corpus. It returns one `{ id, category, evidence }` result per unit, where evidence is null or `{ sourceId, quote }`. Categories remain personal/project fact, general factual assertion, advice/opinion/question, or uncertain. Mixed sentences must be factual, including factual premises inside advice or questions. Pure advice must have null evidence; advice with evidence is contradictory and blocks assessment.

The application owns canonical UTF-16 boundaries and validates the entire ID set before evidence processing. Missing, duplicate, unknown IDs, malformed results and limits block assessment without accepting partial evidence. Reports retain every canonical unit, with null categories when classification is unavailable or ambiguous, plus bounded structural diagnostics (at most 200, containing only reason codes and canonical IDs). Invalid schema produces a schema diagnostic rather than persisting raw validation errors or model output. Whole-unit attribution (`whole-unit-attribution-v2`) compares evidence to the entire unit with whitespace normalization. The drafting prompt encourages separate sentences for personal facts and general advice. No clause parsing, automatic repair, semantic approval or additional model calls are introduced.

Evidence status and claim classification are separate:

- `exact_match`: the entire canonical unit equals an exact quotation in the specified retrieved excerpt, allowing whitespace-only differences. At least 12 characters are required. This establishes attribution, not truth.
- `plausible_paraphrase`: the assessor proposed evidence whose ID/quotation pass local validation, but the body text differs. Plausibility is the assessor's suggestion, not deterministic entailment verification. The artifact remains blocked even if the paraphrase seems reasonable.
- `unsupported`: a factual assertion has no proposed evidence. General technical guarantees, statistics, research claims and embedded factual premises also require support.
- `invalid_reference`: unknown source, fabricated/altered quotation, missing reference component or insufficient quotation length. Invalid model-supplied identifiers and quotes are not preserved in findings.

Uncertain classifications, omitted units, invalid contracts, paraphrases and unsupported/invalid references block ordinary draft storage. Existing conservative English personal/project/metric heuristics additionally inspect every uncovered occurrence; an assessor advice label cannot override them. Whole-unit coverage does not prove that the model classified every implied assertion correctly. The model may miss implied claims, negation or contradictions, and exact excerpts can be false, outdated or misleading. Non-English and indirect claims still need careful human review. No automatic repair loop or truth guarantee is provided.

Accepted drafts retain the existing `claims: [{ text, sourceId, quote }]` interface, constructed from canonical whole units by application validation. They add a versioned assessment report with classifications, findings, body/snapshot hashes and separate assessment model/usage metadata. `review.required: true`, limitations and missing-evidence warnings remain mandatory. `evidence_linked` and `no_personal_claims` are review classifications, never factual certification. Historical drafts remain readable without retroactive assessment.

The knowledge infrastructure hashes source bytes and refreshes unsafe, edited or deleted sources before retrieval. The application captures the source IDs, document IDs, hashes, locations, excerpts and corpus revision in an isolated snapshot, binds assessment to its digest, and checks that digest before commit. Models cannot supply authoritative provenance. This is correspondence to the retrieved snapshot, not a claim that files remain current at future publication or that a compromised local database is trustworthy.

Direct drafting now uses two logical model operations; the agent adds one planning operation. Both stages use the configured model with separate prompts and token usage records. Existing bounded SDK retries and the overall deadline still apply. No automatic retries of blocked content, repair calls, new retrieval, vector store or agent framework are added. Pipeline/policy versions, provider/model, preferences and knowledge participate in both idempotency fingerprints. Existing keys from older pipeline versions conflict rather than silently replaying an assessment under changed policy.

## Private blocked review artifacts

Migration 3 adds separate review-artifact storage and nullable references on run/execution records. Valid bounded generated bodies are retained by default when grounding fails or assessment fails/refuses/times out/is cancelled. If ancillary generation validation fails but a bounded body is available to the service, only that body is retained with safe application warnings. Unparseable provider responses and invalid/oversized bodies are not recoverable artifacts. A process crash before persistence may also lose an in-memory body; interrupted-run recovery remains deferred.

Artifacts have `status: blocked`, `publishable: false`, `reviewRequired: true`, revision 1, a null parent-revision reference, body/evidence hashes, provenance, generation metadata, a failure code and any validated assessment report. Revision fields prepare for future edits/reassessment; there is no editing, promotion, reassessment or approval endpoint. Artifact insertion and the generating run's failed state commit atomically. The parent agent run receives the same artifact reference. Failed idempotency keys keep returning `PREVIOUS_FAILURE` and the retained artifact reference without additional calls.

Use `npm run artifacts -- list`, `npm run artifacts -- get UUID`, and `npm run artifacts -- delete UUID`. MCP exposes `list_review_artifacts`, `get_review_artifact` and `delete_review_artifact`. Lists contain safe summaries only; content/evidence require explicit retrieval. Ownership checks apply to all three operations. Reads use `read_local`; deletion requires `delete_local`, granted by local CLI/MCP composition but never included in the planner allowlist. Ordinary draft lists exclude artifacts.

Safe run diagnostics remain `{ scope, reason, index }` with their historical meanings; new assessment findings live in the artifact/report. Failures and run records may expose an application-generated artifact UUID, never its body or evidence. Raw provider errors and arbitrary assessor explanations are never persisted. Existing diagnostics from migrations 1/2 remain readable and are not reconstructed from absent historical output.

Artifacts remain in private local storage until explicit deletion. Deleting one removes its payload and clears parent/child references while retaining safe failed execution history and idempotency reservations. It does not delete existing request provenance snapshots, source documents, database free space/WAL or backups. Storage is not encrypted. Review sensitive factual excerpts and the extra provider call before supplying private material.

Neither artifacts nor ordinary drafts authorize external actions. Human review remains required, and future publication still needs persistent approval bound to exact payload/account/revision, a permitted integration, idempotency and authoritative outcome evidence.

## Private storage and operating limits

Sources, extracted passages, FTS indexes, journals and temporary extraction files live under ignored `knowledge/`. The public `knowledge.example/` contains instructions only and is never indexed by default. `.linkedout/` retains private provenance/execution snapshots; removing a source does not purge historical drafts, database free space or backups. Git ignore rules prevent ordinary accidental additions, not `git add --force`, pre-existing tracked files, or disclosure through screenshots/terminal output.

The index follows no symbolic links and accepts only regular supported files. Limits: 100 documents, directory depth eight, 8 MiB per file, 32 MiB total source bytes per refresh, 500000 extracted characters/100 PDF pages per document and 5000 passages overall. Invalid documents are skipped individually, with safe identifier/code diagnostics and missing-evidence warnings; malformed content is not silently treated as a fact. PDF extraction has a 15-second deadline and participates in drafting cancellation. It is not a hardened OS sandbox.

`npm run knowledge -- index` refreshes the cache and returns counts/diagnostics. `npm run knowledge -- search --query "..."` previews local evidence without credentials or model calls. Drafting refreshes automatically. Use an absolute `LINKEDOUT_KNOWLEDGE_DIR` ending in `knowledge` for MCP clients launched from another working directory. Keep the folder ignored in any containing repository. See [knowledge organization and setup](../knowledge.example/README.md).

## Verification

Automated tests cover real synthetic PDF extraction and page references; Markdown/text decoding; malformed, empty, missing-parser and oversized inputs; source edits/deletions; FTS search sanitization/ranking/budgets; unknown/mismatched citations; invented personal claims; mandatory review; both drafting modes and idempotency; no remote fetching; safe diagnostics/logs; and actual Git ignore behavior in an isolated repository. No personal CV is committed or used as a fixture.

Linux CI installs Poppler and sets `LINKEDOUT_REQUIRE_PDF_TESTS=1` so PDF tests cannot silently skip. On other hosts those extraction tests report an explicit skip if the native utility is missing; text/Markdown and missing-tool tests still run. Existing OpenAI SDK fixtures remain deterministic and do not establish live model grounding quality. Live generation verification remains subject to configured model access and network availability.

Two-stage implementation verification uses synthetic knowledge and local HTTP fixtures only. No paid OpenAI calls were made; live assessment quality remains for owner verification. The smoke command checks completed assessment metadata as well as persisted drafts.
